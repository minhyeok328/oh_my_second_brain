# RAG 검색 실패 사례

## 답변 상태

이 노트는 실제 장애 목록이 아니라 RAG 답변이 틀렸을 때 실패 위치를 조사하기 위한 미답변 질문 템플릿이다. 아래 증상과 원인은 관찰·가설로 기록하고 재현 결과가 없으면 확정하지 않는다.

## route 조사

- 관찰 후보: 특정 식당명 질문이 embedding 경로로 가거나 분위기 기반 질문이 fixed 경로로 간다.
- 가설: router prompt의 예시와 기본 경로가 질문 유형을 충분히 구분하지 못한다.
- 확인 질문: expected route와 실제 route가 다른가? [[조건부 엣지는 상태에 따라 다음 실행 경로를 선택한다]]의 분기 입력을 기록했는가?
- 답변 상태: 미답변

## payload 조사

- 관찰 후보: route는 맞지만 `restaurant`, `menu`, `category`, `tag`, `review` 슬롯이 비거나 다른 key에 들어간다.
- 가설: slot schema 설명과 실제 DB 필드 의미가 다르거나 사용자 표현의 alias가 빠졌다.
- 확인 질문: 원문 질문, schema와 추출 결과를 같은 실행에서 비교했는가? [[함수 호출은 자연어 요청을 구조화된 도구 입력으로 바꾼다]]의 입력 계약을 만족하는가?
- 답변 상태: 미답변

## target 조사

- 관찰 후보: 슬롯은 기대값과 맞지만 기대 식당이 검색 후보에 없다.
- 가설: category·tag·menu·review 검색 경로, 관계 테이블 조인 또는 후보 교집합이 대상을 탈락시켰다.
- 확인 질문: 각 필터를 하나씩 적용할 때 후보 집합이 어디에서 사라지는가? [[검색기는 질문과 관련된 근거 후보를 좁힌다]]의 후보 식별자를 남겼는가?
- 답변 상태: 미답변

## retrieval 조사

- 관찰 후보: `used_restaurant_list`가 비거나 기대한 최소 후보 수에 못 미친다.
- 가설: top-k, 유사도 임계값, 후보 병합 또는 평가 DB 상태가 맞지 않는다.
- 확인 질문: 검색 전 전체 후보 수와 검색 후 사용 후보 수, DB snapshot과 평가 질문 버전을 함께 남겼는가?
- 답변 상태: 미답변

## answer 조사

- 관찰 후보: 후보에 기대 식당이 있지만 답변이 다른 식당을 말하거나 필수 정보를 빠뜨린다.
- 가설: 생성 프롬프트가 후보 밖 정보 금지와 필수 출력 항목을 충분히 제한하지 못한다.
- 확인 질문: 모델 입력에 전달한 실제 후보와 최종 답변을 비교했는가? [[프롬프트는 모델에 전달하는 작업 계약이다]]의 근거 사용 규칙이 있는가?
- 답변 상태: 미답변
