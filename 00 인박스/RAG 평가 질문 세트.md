# RAG 평가 질문 세트

## 답변 상태

이 노트는 [[SKN26 3차 PICKLE 맛집 추천 챗봇]]의 평가 구조를 다시 확인하기 위한 미답변 작업 큐다. 기존 기록의 수치와 파일 경로는 현재 프로젝트 소스에서 재검증하기 전까지 확정 사실로 사용하지 않는다.

## 기존 관찰 — 재검증 필요

- 기존 기록에는 fixed 20개와 embedding 30개, 총 50개 사례가 있었다.
- 기존 기록에는 route 30%, payload 25%, target 25%, answer 10%, retrieval 10% 가중치가 있었다.
- 확인 질문: 현재 평가 스크립트와 goldset에서도 개수, 필드와 가중치가 같은가?
- 답변 상태: 미답변

## fixed 질문 후보

- 관찰 후보: 특정 식당명, 메뉴명, 사용자명처럼 DB entity가 직접 들어간 질문.
- 예시 질문: `유태우스시 영업시간 알려줘`, `유태우스시에 회전초밥 있어?`
- 가설: 기대 route를 fixed로 두고 필요한 entity가 payload와 검색 target에 남는지 확인할 수 있다.
- 확인 질문: 예시 entity가 현재 DB snapshot에도 존재하며 기대 route 기준이 여전히 유효한가?
- 답변 상태: 미답변

## embedding 질문 후보

- 관찰 후보: 분위기, 상황, 태그, 카테고리처럼 의미 기반 후보 검색이 필요한 질문.
- 예시 질문: `혼밥하기 좋은 초밥 맛집 추천해줘`, `데이트하기 좋은 파스타 맛집 추천해줘`
- 가설: 기대 route를 embedding으로 두고 추출 조건과 사용 후보 수를 함께 볼 수 있다.
- 확인 질문: 현재 태그와 카테고리 분포에서 기대 target과 최소 후보 수를 어떻게 정할 것인가?
- 답변 상태: 미답변

## 평가 축 질문

- route: 질문이 의도한 검색 경로로 갔는가?
- payload: 추출된 key와 값이 질문의 조건을 보존하는가?
- target: 기대 대상을 검색 후보 안에서 찾았는가?
- retrieval: 후보 수와 순위가 정한 기준을 만족하는가?
- answer: 답변이 사용 후보를 근거로 필수 정보를 포함하고 금지 내용을 피하는가?
- 확인 질문: 각 축의 실패가 다른 축의 실패와 중복될 때 어떤 순서로 판정할 것인가?
- 답변 상태: 미답변

## 실행 전 체크

- DB snapshot 또는 데이터 버전을 기록한다.
- goldset 생성 코드, 평가 코드와 모델·프롬프트 식별자를 기록한다.
- 원문 질문, route, payload, 검색 후보, 사용 후보와 최종 답변을 같은 실행 ID로 저장한다.
- 실패는 [[RAG 검색 실패 사례]]의 관찰·가설·답변 상태 형식으로 옮긴다.
