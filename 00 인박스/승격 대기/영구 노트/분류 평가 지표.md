# 분류 평가 지표

태그: #machinelearning #classification #evaluation #llm_wiki

## 한 줄 정의

분류 평가 지표는 모델이 어떤 클래스를 얼마나 잘 맞혔는지 accuracy, precision, recall, F1, ROC-AUC, PR-AUC 등으로 나누어 보는 기준이다.

## 왜 중요한가

분류 문제는 틀리는 방식마다 비용이 다르다. 카드 이탈 예측처럼 이탈 고객이 소수인 문제에서 accuracy만 보면 "대부분 유지 고객이라고 예측하는 모델"도 좋아 보일 수 있다. 따라서 문제의 목적이 놓치면 안 되는 고객 탐지인지, 양성 예측의 신뢰도인지, 전체 ranking 품질인지 먼저 정해야 한다.

## 핵심 개념

- accuracy: 전체 중 맞힌 비율이다.
- precision: 양성이라고 예측한 것 중 실제 양성 비율이다.
- recall: 실제 양성 중 모델이 찾아낸 비율이다.
- F1: precision과 recall의 균형이다.
- ROC-AUC: threshold 변화에 따른 분리 능력을 본다.
- PR-AUC: 양성 클래스가 적을 때 ranking 품질을 더 민감하게 본다.
- train/test 지표를 같이 봐야 과적합 여부를 판단할 수 있다.

## 프로젝트 예시

[[SKN26 2차 신용카드 고객 이탈 분석]]의 `model_evaluation.md`는 Unknown Income 보정을 위해 XGBoost 기반 income 분류 실험을 기록했다.

- multi-class income test: accuracy 0.5989, recall 0.4704, F1 0.4607, ROC-AUC 0.8428
- multi-class income train: accuracy 0.8044, recall 0.7481, F1 0.7615, ROC-AUC 0.9765
- binary income test: accuracy 0.9027, recall 0.9489, F1 0.8886, ROC-AUC 0.9676
- binary income train: accuracy 0.9514, recall 0.9903, F1 0.9434, ROC-AUC 0.9955

이 결과는 "모델을 바꿔야 한다"보다 먼저 "문제 정의를 5-class로 유지할지 Low/High binary로 재구성할지"를 묻게 한다.

## 언제 쓰는가

- 이탈, 사기, 스팸, 리스크처럼 클래스별 오류 비용이 다른 문제를 평가할 때
- train 성능과 test 성능 차이로 과적합을 점검할 때
- multi-class 문제를 binary 문제로 재정의해도 되는지 비교할 때
- 모델 성능을 비즈니스 전략으로 설명해야 할 때

## 언제 쓰면 안 되는가

- 데이터 split이나 라벨 정의가 틀린 상태에서 지표만 비교할 때
- test set을 반복적으로 보며 하이퍼파라미터를 고르는 방식으로 지표를 오염시킬 때
- 운영 목표가 ranking이나 비용 최소화인데 accuracy만 보고 모델을 선택할 때

## 실패 조건

- 이탈 고객이 적은데 accuracy만 높으면 실제 위험 고객을 놓칠 수 있다.
- train 지표가 test보다 지나치게 높으면 과적합 가능성을 먼저 봐야 한다.
- ROC-AUC가 높아도 실제 threshold에서 recall이나 precision이 낮을 수 있다.
- multi-class 평균 지표는 특정 소수 클래스 실패를 가릴 수 있다.
- Unknown 값을 예측한 결과는 정답 라벨이 없으면 성능 평가가 아니라 추론 결과로만 해석해야 한다.

## 먼저 확인할 질문

- 이 문제에서 더 위험한 오류는 false positive인가, false negative인가?
- 클래스 분포가 불균형한데 accuracy만 보고 있지는 않은가?
- train/test 지표 차이가 설명 가능한 수준인가?
- 현재 지표가 실제 리텐션 전략이나 운영 의사결정에 연결되는가?
