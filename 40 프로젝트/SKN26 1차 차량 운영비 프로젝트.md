# SKN26 1차 차량 운영비 프로젝트

## 프로젝트 사실

- 차량 제원·연비·유가·정비 기준과 사용자 주행 조건을 결합해 월간 운영비를 비교하는 팀 프로젝트다. 보험료·금융 비용과 개인화된 운행 환경은 계산 범위에서 제외되어, 결과는 실제 총소유비용 예측보다 동일 조건의 비교 기준선에 가깝다. (근거: `README.md` 1장, 2장, 8장)
- 저장소에서 확인되는 구성은 Python, Streamlit, MySQL 연동 코드와 외부 데이터 수집 모듈이다. (근거: `README.md` 3-3절, `main.py`, `API_Side`)
- 개인 포트폴리오는 진행 기간을 `2026-02-05 ~ 2026-02-06`으로 적지만, 저장소 README에는 기간이 없다. 따라서 기간은 개인 서술로만 기록한다. (근거: 포트폴리오의 차량 운영·관리 비용 계산 시스템 상세 모달, 2026-08-11 확인)

## 팀 산출물

- 팀은 차량 검색, 가격·연비·유가 조회, 주행 조건 입력, 정비비·연료비·차량세 계산과 결과 표시를 하나의 Streamlit 흐름으로 연결했다. 이 문장은 팀 결과를 설명하며 개인 소유권을 뜻하지 않는다. (근거: `README.md` 2-2절, 3-3절, `main.py`)
- 연료·정비·고정 비용을 각각 계산한 뒤 월 단위로 환산하는 계산 구조와, API·DB·UI를 나눈 디렉터리 구조가 문서화되어 있다. (근거: `README.md` 3-1절~3-3절)

## 직접 기여

- README 역할 표는 서민혁의 담당을 `연비 API / CSV 로드 및 파싱`으로 명시한다. 포트폴리오도 공공 연비 API 수집·응답 정규화와 CSV 가공을 직접 역할로 기록한다. (근거: `README.md` 프로젝트 팀 및 역할, 포트폴리오 상세 모달)
- `CarOil.py`에는 API 결과가 단일 객체일 때 목록으로 바꾸고 차량명·제조사·연료·연비·연식 등의 필드를 일정한 순서로 추출하는 코드가 있다. 코드의 존재만으로 작성자를 판정하지 않았으며, 개인 기여 귀속은 앞의 역할 표와 개인 포트폴리오에 근거한다. (근거: `API_Side\CarOil.py`)
- 포트폴리오는 비용 모델과 전체 데이터 흐름의 문서화도 직접 기여로 적는다. README 역할 표에는 이 문서화 역할이 별도로 귀속되지 않으므로, 이는 개인 서술 범위로만 남긴다. (근거: 포트폴리오 상세 모달, `README.md` 역할 표)

## 의사결정과 근거

- 외부 API의 단일 항목과 복수 항목 응답을 같은 목록 형태로 정규화했다. 뒤 단계가 동일한 자료 구조를 받을 수 있게 한 선택이며, 이 사례는 [[DataFrame은 열 단위 데이터 변환을 구조화한다]]와 연결된다. (근거: `CarOil.py`, 포트폴리오 기술 설계와 판단)
- 서로 다른 주기의 비용을 월 단위로 환산하고 계산 로직과 비용 입력값을 분리한 것은 팀 설계다. 개인 단독 결정으로 귀속하지 않는다. (근거: `README.md` 3-1절, 3-2절)

## 실패·디버깅

- README와 포트폴리오에는 서민혁에게 귀속된 구체적인 장애·수정 사건이 기록되어 있지 않다. 발생하지 않았다고 단정하지 않고 `근거 없음`으로 둔다. (근거: `README.md` 전체 회고, 포트폴리오 상세 모달)
- 확인된 팀 산출물의 한계는 제한된 차량 범위, 개인화 조건 미반영, 보험·금융 비용 제외와 UI 비교성 개선 필요다. (근거: `README.md` 8장)

## 회고
