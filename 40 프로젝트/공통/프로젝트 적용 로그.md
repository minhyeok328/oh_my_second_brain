## 프로젝트 경험 — 1차 차량 TCO

- 상황: 차량 유지비를 구매 가격과 분리해 월 단위 TCO로 비교해야 했다.
- 선택 또는 원인: Streamlit 상태, MySQL 조회, 외부 차량·유가 데이터 수집과 월 유지비 계산을 한 흐름으로 연결했다.
- 근거: [[SKN26 1차 차량 운영비 프로젝트]], [[Streamlit 세션 상태는 재실행 사이의 값을 보존한다]], [[SELECT와 WHERE는 조회 범위와 조건을 분리한다]].
- 결과: 차량 모델 검색, 연비·유가·정비 주기 조회와 월 유지비 계산 흐름을 Streamlit UI로 묶었다.
- 다음에 적용할 원칙: DB 입력의 parameter binding, 외부 요청 실패 처리와 계산 단위 기준을 먼저 확인한다.

## 프로젝트 경험 — 2차 카드 이탈 예측

- 상황: 카드 이탈을 고객 행동 패턴과 고객 맥락으로 설명하고 모델 실험을 비교해야 했다.
- 선택 또는 원인: EDA와 특성 공학, 모델 비교, MLflow 실험 관리와 Docker Compose 실행 환경을 사용했다.
- 근거: [[SKN26 2차 신용카드 고객 이탈 분석]], [[특성 공학은 모델보다 먼저 데이터 표현을 개선한다]], [[MLflow는 실험 조건과 결과를 함께 추적한다]], [[Docker Compose는 여러 컨테이너의 실행 계약을 한곳에 모은다]].
- 결과: 모델별 성능 비교, MLflow 모델 로드, Streamlit 대시보드와 pipeline API를 구성했다.
- 다음에 적용할 원칙: Unknown income 처리 근거, class 불균형 지표, 학습·평가 분리와 artifact 식별자를 함께 기록한다.

## 프로젝트 경험 — 3차 PICKLE RAG 챗봇

- 상황: 맛집 추천에서 DB에 존재하는 후보를 근거로 답하고 RAG 실패 단계를 분리해야 했다.
- 선택 또는 원인: fixed·embedding route, slot 추출, DB 검색, 후보 기반 생성과 goldset 평가를 연결했다.
- 근거: [[SKN26 3차 PICKLE 맛집 추천 챗봇]], [[RAG의 성능은 검색 단계의 품질에서 시작된다]], [[LangGraph는 상태 전이를 명시해 LLM 흐름을 제어한다]], [[RAG 평가는 검색과 생성을 분리해서 측정해야 한다]].
- 결과: route, payload, target, answer, retrieval을 나누어 확인하는 기존 평가 흐름을 남겼다.
- 다음에 적용할 원칙: [[RAG 평가 질문 세트]]와 [[RAG 검색 실패 사례]]에서 관찰, 가설과 확인된 답을 분리한다.

## 프로젝트 경험 — 4차 LG Home

- 상황: 가전 검색, 사용설명서 질의응답, 찜 기반 개인화와 후속 질문을 한 서비스에서 처리해야 했다.
- 선택 또는 원인: Django SSR, LangGraph 상담 흐름, 매뉴얼 검색과 JSON API를 구성했다.
- 근거: [[SKN26 4차 LG Home AI 가전 상담]], [[Django 챗봇은 대화 상태와 요청 경계를 함께 관리해야 한다]], [[벡터 저장소는 임베딩과 메타데이터를 함께 관리해야 한다]], [[CSRF 방어는 브라우저 세션 요청의 출처를 검증한다]].
- 결과: Django SSR 기반 가전 서비스, 상담 챗봇, 매뉴얼 RAG와 AJAX JSON API 구조를 프로젝트 노트에 남겼다.
- 다음에 적용할 원칙: 후속 질문 상태, 제품군별 검색 조건, 인증 만료와 API 실패 UX를 별도 경계로 점검한다.

## 개인 해석 — 4차 이후 React 확장

- 상황: 공식 4차 프로젝트 종료 후 Django SSR 구조를 React SPA와 Django JSON API로 분리해 보고 싶었다.
- 선택 또는 원인: `4th_project_change_react`에서 프론트 렌더링과 Django API 책임을 나누는 개인 확장 실험을 진행했다.
- 근거: [[SKN26 4차 LG Home AI 가전 상담]]의 개인 확장 기록, [[React SPA는 화면 상태와 서버 상태의 경계를 분명히 해야 한다]], [[Django JSON API는 화면과 서버 책임을 분리한다]].
- 결과: React SPA로 분리해 보니 Django는 화면 조립보다 DB, 인증, LLM 호출 결과를 JSON API로 제공하는 쪽이 더 명확해 보였다는 기존 개인 회고를 남겼다.
- 다음에 적용할 원칙: 공식 팀 산출물과 프로젝트 종료 후 개인 실험의 출처를 계속 분리한다.
