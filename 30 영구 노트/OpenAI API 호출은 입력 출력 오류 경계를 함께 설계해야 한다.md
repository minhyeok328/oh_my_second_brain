# OpenAI API 호출은 입력 출력 오류 경계를 함께 설계해야 한다

서비스의 OpenAI API 호출은 모델과 프롬프트를 보내는 한 줄이 아니라 입력 검증, 응답 해석, 실패 처리를 묶은 경계다. 공식 빠른 시작은 요청과 응답의 기본 형태를 보여 주고, 오류 문서는 인증·요청·속도 제한·서버 오류처럼 호출이 실패하는 여러 경우를 구분한다. 성공 응답만 가정하면 모델 기능보다 네트워크와 파싱 경계에서 서비스가 먼저 깨진다.

입력에서는 민감정보와 길이 제한을 확인하고 [[프롬프트는 모델에 전달하는 작업 계약이다]]의 책임을 한 호출에 좁힌다. 출력이 코드로 이어지면 [[함수 호출은 자연어 요청을 구조화된 도구 입력으로 바꾼다]]의 스키마를 검증한다. 실패 시에는 재시도 가능한 오류와 사용자 수정이 필요한 오류를 나누고, 요청 ID와 지연·사용량을 기록해야 원인을 재현할 수 있다.

모든 오류에 같은 재시도를 적용하는 것은 위험하다. 잘못된 인증이나 스키마 오류는 반복해도 고쳐지지 않고, 속도 제한에 즉시 재시도하면 부하만 키운다. 또한 [[LLM은 다음 토큰 확률로 문맥에 맞는 출력을 만든다]]는 특성상 HTTP 성공도 내용의 정확성을 보장하지 않으므로, 비즈니스 검증과 사용자에게 보여 줄 fallback은 API 성공 여부와 별도로 설계해야 한다.
