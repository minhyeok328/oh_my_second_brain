# RAG의 성능은 검색 단계의 품질에서 시작된다

RAG에서 생성 모델이 답을 잘 쓰기 전에 먼저 확보해야 하는 것은 질문에 맞는 근거다. 원래 RAG 연구도 검색기가 가져온 문서를 생성기가 조건으로 사용하도록 결합했고, 현재 LangChain 문서도 검색한 외부 지식을 런타임 컨텍스트로 공급하는 일을 RAG의 토대로 설명한다. 따라서 관련 문서가 후보에 들어오지 않으면 그 문서는 검색 근거나 출처 기반 검증 자료로 생성 단계에 제공될 수 없다. 모델의 파라미터 지식에서 우연히 같은 정보를 생성할 수 있더라도, 이는 안정적인 검색 근거 기반 해결책이 아니다.

이 관점에서는 실패를 한 덩어리로 보지 않는다. [[검색기는 질문과 관련된 근거 후보를 좁힌다]]에서 후보를 기록하고, [[RAG 평가는 검색과 생성을 분리해서 측정해야 한다]]에서 검색 누락과 근거 무시를 따로 측정해야 한다. [[벡터 저장소는 임베딩과 메타데이터를 함께 관리해야 한다]]의 필터와 원문 식별자도 같은 이유로 필요하다.

다만 검색 품질이 높다고 답변 품질이 자동으로 보장되지는 않는다. 관련 근거가 있어도 [[프롬프트는 모델에 전달하는 작업 계약이다]]가 근거 사용과 모르는 경우의 처리를 정하지 않으면 모델이 후보 밖 내용을 덧붙일 수 있다. 반대로 외부 근거가 필요 없는 문장 변환이나 계산은 검색 단계를 붙이는 것이 지연과 복잡성만 늘릴 수 있다.
