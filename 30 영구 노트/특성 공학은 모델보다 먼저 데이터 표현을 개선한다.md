# 특성 공학은 모델보다 먼저 데이터 표현을 개선한다

## 주장

특성 공학은 원시 값을 학습기가 사용할 수 있는 표현으로 바꾸는 일이며, 모델 종류를 늘리기 전에 입력의 단위·범주·시간·결측 표현이 과업에 맞는지 검토하게 한다. [[DataFrame은 열 단위 데이터 변환을 구조화한다]]는 구현 단위를 제공하고, [[학습 데이터와 평가 데이터는 모델 선택 전에 분리해야 한다]]는 변환을 학습할 데이터 경계를 정한다.

## 연결

[[머신러닝 강의]]와 [[데이터 분석 강의]]에서 확인한 전처리·스케일링·EDA 실습을 내 관점으로 연결하면, 표현 선택의 근거와 전후 통계를 기록해야 [[분류 평가는 클래스 불균형에 맞는 지표를 선택해야 한다]]의 결과도 재현 가능하게 해석할 수 있다.

## 한계와 반례

모든 모델이 같은 변환에서 이득을 얻는 것은 아니며, 불필요한 변환은 신호를 훼손할 수 있다. 전체 데이터로 스케일러·인코더를 먼저 맞추거나 예측 시점에 알 수 없는 값을 만들면 성능 향상이 아니라 데이터 누수다. 특성 중요도 역시 인과관계를 증명하지 않는다.

- 2026-08-11: scikit-learn 공식 교차 검증 문서에서 평가 데이터를 보고 전처리하면 일반화 성능 추정에 정보가 누수될 수 있음을 확인했다.
