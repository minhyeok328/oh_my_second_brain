# 프론트엔드 상태는 권한 경계와 함께 정리해야 한다

## 주장

같은 SPA에서 인증 주체나 접근 범위가 바뀌면 이전 범위에서 가져온 서버 상태를 새 범위의 화면에 그대로 재사용하지 않아야 한다. 데이터를 달라지게 하는 인증 방식·세션 식별자를 query key에 포함해 캐시를 분리하고, 전환이 끝나는 지점에서는 이전 query와 인증 상태를 정리해야 한다. TanStack Query 공식 문서는 query function의 결과를 달라지게 하는 변수를 key에 포함해 데이터를 독립적으로 캐시하라고 설명한다.

## 프로젝트 경험

[[SKN26 Final HumouR AI HR 채용 보조]]에서는 account 세션과 API Key 제한 세션을 구분하고, 실제 API Key 대신 새로 만든 불투명 세션 식별자를 query key에 포함한다. 로그아웃·만료 때 캐시와 저장된 API Key를 정리하는 흐름도 확인된다. [[HumouR README와 포트폴리오]]의 개인 서술은 이 경계 설계를 직접 경험한 것으로 기록하지만, 제한 공유 기능 전체나 서버 권한 구현의 개인 소유권을 뜻하지 않는다.

- 공식 근거: [TanStack Query Query Keys](https://tanstack.com/query/latest/docs/framework/react/guides/query-keys), [TanStack Query QueryClient](https://tanstack.com/query/latest/docs/reference/QueryClient), [React Preserving and Resetting State](https://react.dev/learn/preserving-and-resetting-state)

## 한계와 반례

프론트엔드의 route, UI, query key와 캐시 분리는 권한 검사가 아니다. 서버는 요청마다 자원 소유권과 허용 범위를 검증해야 하며, 클라이언트 경계는 이전 데이터 노출과 잘못된 화면 재사용을 줄이는 보조 장치다. 사용자와 무관한 공개·불변 데이터는 인증별로 중복 캐시할 필요가 없고, 지속 캐시를 사용한다면 메모리 `clear()`만으로 충분한지도 별도로 확인해야 한다.
