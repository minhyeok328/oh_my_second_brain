# 프롬프트는 모델에 전달하는 작업 계약이다

프롬프트는 단순한 질문 문장이 아니라 [[LLM은 다음 토큰 확률로 문맥에 맞는 출력을 만든다|모델]]이 수행할 목표, 사용할 근거, 지켜야 할 제약, 반환 형식을 한 요청 안에서 정하는 작업 계약이다. 이 계약이 구체적일수록 결과가 틀렸을 때 입력 근거, 지시, 형식 중 어느 조건을 고쳐야 하는지 평가할 수 있다.

코드가 출력을 소비한다면 자연어 형식 지시만 반복하기보다 [[함수 호출은 자연어 요청을 구조화된 도구 입력으로 바꾼다]]처럼 스키마로 검증 범위를 좁힌다. RAG 답변에서는 [[RAG의 성능은 검색 단계의 품질에서 시작된다]]가 준 근거만 사용하고 근거가 부족할 때 멈추는 조건을 명시한다. 프롬프트 변경은 [[RAG 평가는 검색과 생성을 분리해서 측정해야 한다]]의 같은 평가 세트로 비교해야 한다.

프롬프트는 데이터 품질이나 권한 검사를 대신하지 못한다. 없는 정보를 길게 금지해도 검색 후보가 틀렸거나 애플리케이션이 민감한 입력을 넘겼다면 문제는 남는다. 지나치게 긴 지시와 예시는 비용을 키우고 서로 충돌할 수 있으므로, 측정된 실패를 고치는 조건만 남기고 모델·도구 변경 때 회귀 평가를 반복해야 한다.
