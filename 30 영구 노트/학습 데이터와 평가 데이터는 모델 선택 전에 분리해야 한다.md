# 학습 데이터와 평가 데이터는 모델 선택 전에 분리해야 한다

## 주장

평가 데이터는 학습과 모델 선택에 사용하지 않은 사례로 남겨야 일반화 성능을 독립적으로 추정할 수 있다. 그래서 [[특성 공학은 모델보다 먼저 데이터 표현을 개선한다]]의 변환도 학습 부분에서만 맞추고, [[분류 평가는 클래스 불균형에 맞는 지표를 선택해야 한다]]의 최종 값은 보류한 평가 부분에서 계산해야 한다.

## 연결

[[머신러닝 강의]]의 분류·회귀·교차 검증 예제를 내 관점으로 정리하면, `random_state`와 분할 기준을 기록하고 검증용 선택과 최종 평가를 구분해야 실험 비교가 재현된다. 이 기록은 [[MLflow는 실험 조건과 결과를 함께 추적한다]]의 run 조건에도 포함할 수 있다.

## 한계와 반례

무작위 `train_test_split`이 언제나 적절한 것은 아니다. 시간 순서, 동일 사용자·장비의 반복 관측, 희소한 클래스가 있으면 시간 기반·그룹 기반·층화 분할이 필요할 수 있다. 한 번의 holdout 점수만으로 분산이나 배포 후 분포 변화를 설명할 수도 없다.

- 2026-08-11: scikit-learn 공식 교차 검증 문서에서 평가 데이터로 모델을 조정하면 정보 누수로 일반화 성능 추정이 훼손됨을 확인했다.
