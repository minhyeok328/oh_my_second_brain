# 함수 호출은 자연어 요청을 구조화된 도구 입력으로 바꾼다

함수 호출에서 모델의 책임은 사용자의 자연어 의도를 애플리케이션이 정의한 함수 이름과 JSON Schema 인자로 표현하는 데까지다. OpenAI 공식 가이드의 흐름도 모델이 도구 호출을 만들고 애플리케이션이 코드를 실행한 뒤 결과를 다시 전달하는 단계로 나뉜다. 따라서 모델이 함수 실행 권한을 직접 갖는다고 보면 경계를 잘못 이해한 것이다.

좋은 스키마는 [[프롬프트는 모델에 전달하는 작업 계약이다]]를 코드가 검증할 수 있는 필드와 열거 값으로 좁힌다. 호출 결과는 [[OpenAI API 호출은 입력 출력 오류 경계를 함께 설계해야 한다]]에 따라 파싱 실패, 누락 값, 도구 오류를 별도로 처리해야 한다. 여러 도구가 이어질 때는 [[LangGraph 상태는 노드 사이의 데이터 계약이다]]에 호출 인자와 실행 결과를 구분해 기록할 수 있다.

구조화된 인자도 신뢰할 수 있는 권한 증명은 아니다. strict schema는 형태를 제한할 뿐 값의 사실성, 사용자 권한, 작업의 안전성을 보장하지 않는다. 결제·삭제·외부 전송처럼 영향이 큰 함수는 애플리케이션이 값 검증과 승인 절차를 수행해야 하며, 사용자가 이미 UI에서 구조화 값을 골랐다면 다시 모델로 추출하는 단계는 불필요하다.
