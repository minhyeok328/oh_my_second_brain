# JSON

태그: #json #web #api #llm_wiki

## 한 줄 정의

키-값 구조와 배열로 데이터를 표현하는 경량 텍스트 데이터 형식이다.

## 왜 중요한가

웹 API, 설정 파일, LLM 도구 호출, JavaScript 객체 교환은 대부분 JSON을 통한다. 구조를 읽고 검증할 수 있어야 시스템 간 데이터 흐름을 안정적으로 연결할 수 있다.

## 핵심 개념

- 객체는 `{}` 안의 키-값 쌍으로 표현한다.
- 배열은 `[]` 안의 순서 있는 값 목록이다.
- 문자열, 숫자, 불리언, null, 객체, 배열을 값으로 가질 수 있다.

## 예제

```json
{"name": "Min", "skills": ["python", "django"], "active": true}
```

## 실무 활용

OpenAPI 응답 파싱, 프론트엔드 fetch 처리, LLM Function Calling 스키마, 설정 파일 저장에 사용한다.

## 내 말로 다시 설명

JSON은/는 강의에서 나온 개념을 정의, 사용 조건, 주의점, 연결 개념으로 다시 설명하기 위한 LLM wiki 원자 노트다. 단순 암기보다 실제 문제에서 언제 꺼내 쓸지 판단하는 데 초점을 둔다.

## 언제 쓰는가

- 강의 실습 코드에서 같은 개념을 다시 만날 때
- 프로젝트에서 관련 오류나 설계 결정을 설명해야 할 때
- [[JavaScript 객체 리터럴]], [[OpenAPI]], [[Function Calling]]와 함께 문제 원인을 좁힐 때

## 언제 쓰면 안 되는가

- 구체적인 API 버전, 파라미터, 보안 정책이 필요한 경우에는 공식 문서를 먼저 확인한다.
- 예제 하나만 보고 모든 상황에 일반화해야 할 때는 보류한다.
- 이미 더 좁고 구체적인 노트가 있는 경우에는 그 노트로 이동한다.

## 자주 헷갈리는 점

- 이름이 비슷한 인접 개념과 책임 범위가 다를 수 있다.
- 강의 예제의 상황과 실제 프로젝트의 데이터, 환경, 버전 차이를 분리해야 한다.
- "동작한다"와 "운영에서 유지보수 가능하다"는 다른 기준이다.
