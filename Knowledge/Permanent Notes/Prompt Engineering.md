# Prompt Engineering

태그: #llm #prompt #llm_wiki

## 한 줄 정의

LLM이 원하는 방식으로 추론하고 출력하도록 지시문, 예시, 제약을 설계하는 기술이다.

## 왜 중요한가

같은 모델도 프롬프트 구조에 따라 정확도, 일관성, 안전성이 크게 달라진다.

## 핵심 개념

- 역할, 목표, 제약, 출력 형식을 명시한다.
- 예시는 모델의 패턴을 유도한다.
- 긴 프롬프트는 근거와 지시를 분리해 관리한다.

## 예제

```text
역할: 데이터 분석가
목표: 결측치 처리 전략 제안
출력: 표 형태
```

## 실무 활용

RAG 답변 형식, 함수 호출 지시, 이미지 생성 조건, 평가 프롬프트에 사용한다.

## 내 말로 다시 설명

Prompt Engineering은/는 강의에서 나온 개념을 정의, 사용 조건, 주의점, 연결 개념으로 다시 설명하기 위한 LLM wiki 원자 노트다. 단순 암기보다 실제 문제에서 언제 꺼내 쓸지 판단하는 데 초점을 둔다.

## 언제 쓰는가

- 강의 실습 코드에서 같은 개념을 다시 만날 때
- 프로젝트에서 관련 오류나 설계 결정을 설명해야 할 때
- [[LLM]], [[Prompt Template]], [[RAG]]와 함께 문제 원인을 좁힐 때

## 언제 쓰면 안 되는가

- 구체적인 API 버전, 파라미터, 보안 정책이 필요한 경우에는 공식 문서를 먼저 확인한다.
- 예제 하나만 보고 모든 상황에 일반화해야 할 때는 보류한다.
- 이미 더 좁고 구체적인 노트가 있는 경우에는 그 노트로 이동한다.

## 자주 헷갈리는 점

- 이름이 비슷한 인접 개념과 책임 범위가 다를 수 있다.
- 강의 예제의 상황과 실제 프로젝트의 데이터, 환경, 버전 차이를 분리해야 한다.
- "동작한다"와 "운영에서 유지보수 가능하다"는 다른 기준이다.

## 확인 질문

- Prompt Engineering을/를 쓰면 어떤 문제를 더 단순하게 설명할 수 있는가?
- 관련 개념과 구분되는 핵심 기준은 무엇인가?
- 실제 프로젝트에 적용하면 먼저 검증해야 할 실패 조건은 무엇인가?
