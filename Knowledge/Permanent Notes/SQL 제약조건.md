# SQL 제약조건

태그: #sql #database #llm_wiki

## 한 줄 정의

데이터가 만족해야 하는 규칙을 데이터베이스 수준에서 강제하는 장치다.

## 왜 중요한가

애플리케이션 검증만으로는 모든 경로를 통제하기 어렵다. 제약조건은 데이터 무결성을 데이터베이스에 고정한다.

## 핵심 개념

- `PRIMARY KEY`는 행 식별자다.
- `NOT NULL`, `UNIQUE`, `CHECK`는 값의 규칙을 제한한다.
- `FOREIGN KEY`는 참조 무결성을 만든다.

## 예제

```sql
email VARCHAR(255) UNIQUE NOT NULL
```

## 실무 활용

회원 이메일 중복 방지, 주문-사용자 관계 보존, 분석 데이터 결측 방지에 사용한다.

## 언제 쓰는가

- 강의 실습 코드에서 같은 개념을 다시 만날 때
- 프로젝트에서 관련 오류나 설계 결정을 설명해야 할 때
- [[SQL DDL]], [[관계형 데이터베이스]], [[Django ORM Model]]와 함께 문제 원인을 좁힐 때

## 언제 쓰면 안 되는가

- 구체적인 API 버전, 파라미터, 보안 정책이 필요한 경우에는 공식 문서를 먼저 확인한다.
- 예제 하나만 보고 모든 상황에 일반화해야 할 때는 보류한다.
- 이미 더 좁고 구체적인 노트가 있는 경우에는 그 노트로 이동한다.

## 자주 헷갈리는 점

- 이름이 비슷한 인접 개념과 책임 범위가 다를 수 있다.
- 강의 예제의 상황과 실제 프로젝트의 데이터, 환경, 버전 차이를 분리해야 한다.
- "동작한다"와 "운영에서 유지보수 가능하다"는 다른 기준이다.
