# SKN26 2차 프로젝트 - 카드 이탈 예측

태그: #project_context #project #skn26 #machine_learning #mlflow

## 한 줄 요약

BankChurners 기반 카드 고객 데이터를 분석해 이탈 위험 신호를 찾고, 여러 ML 모델과 MLflow 실험 관리를 통해 고객 세그먼트별 리텐션 전략을 도출한 프로젝트다.

## 문제 정의

카드 산업은 신규 고객 확보 비용이 높기 때문에 기존 고객의 이탈을 줄이는 것이 중요하다. 단순히 카드 사용 감소만 보는 대신 거래 횟수, 거래 금액, 비활성 기간, 보유 상품 수, 카드 등급을 함께 보고 이탈 선행 신호를 해석했다.

## 사용한 지식

- [[EDA]]: 이탈 고객과 유지 고객의 행동 패턴을 비교한다.
- [[Feature Engineering]]: 소득 Unknown 보정, 카드 활동 지표, 세그먼트 변수를 만든다.
- [[XGBoost]], [[Random Forest]], [[로지스틱 회귀]], [[앙상블 학습]]: 모델별 예측 성능을 비교한다.
- [[MLflow]]: 모델 run, score, artifact를 기록하고 최신 모델을 대시보드에서 로드한다.
- [[FastAPI]]: 파이프라인 상태와 데이터 조회용 API를 제공한다.
- [[Docker Compose]]: Streamlit, MLflow, pipeline API, DB를 함께 실행한다.
- [[Streamlit 기본 UI]]: 분석 대시보드, 모델별 확률, 전략 보고서를 보여준다.

## 프로젝트 예시

- `pipeline\run_etl.py`는 CSV 로드, 컬럼 표준화, DB row 수 확인, 중복 적재 방지를 거쳐 `creditcard_churn` 테이블에 적재한다.
- `pipeline\main.py`는 FastAPI 앱을 만들고 health, dataset router를 등록한다.
- `streamlit\common\mlflow\load_latest_model_by_name.py`는 MLflow experiment에서 최신 run을 찾고 모델 flavor에 맞는 loader로 artifact를 불러온다.
- `model_evaluation.md`는 multi-class income 예측과 Low/High binary 재구성 실험을 분리해 성능을 비교한다.

## 판단 기준

- 모델 성능은 accuracy 하나로 판단하지 않고 recall, F1, ROC-AUC, PR-AUC를 함께 본다.
- Unknown 값을 삭제할지 예측 보정할지는 분석 목적과 실제 운영 영향으로 판단한다.
- MLflow artifact 경로와 모델 flavor는 모델명마다 다를 수 있으므로 loader에 후보 경로와 fallback을 둔다.
- ETL은 재실행 가능해야 하며, 같은 데이터가 반복 적재되지 않아야 한다.

## 개인 회고

- 직접 맡은 부분: 모델링 영역에서 군집화, 차원축소 등 여러 접근을 시도하며 데이터 결측치를 역으로 추정해보려 했다.
- Unknown Income 판단: 시각화로 변수 관계를 봤을 때 Unknown을 없애기에는 영향이 너무 커서 단순 삭제보다 보정과 별도 해석이 필요하다고 느꼈다.
- 성능 저하 판단: multi-class 소득 예측 성능이 낮았을 때 가장 먼저 class 불균형을 의심했다.
- 문제 재정의: Low/High binary 재구성은 단순히 문제를 쉽게 만들기보다 비즈니스 의미를 더 명확하게 만들려는 선택이었다.
- 지표 감각: 이탈자 예측 프로젝트였기 때문에 당시에는 정확도를 더 집중적으로 확인하려 했던 것으로 기억한다. 다만 다음 검증에서는 이탈자 class의 recall, F1도 함께 봐야 한다.
- 협업/도구 경험: MLflow, Docker Compose, CLI git, 브랜치 전략 모두 처음이라 어려웠지만, 한 번 겪고 나니 다음 프로젝트부터는 훨씬 편해졌다.
- 다시 한다면: 결측치 예측을 군집화, 차원축소, 모델링 등 다양한 방향에서 더 끝까지 실험하고, 결과를 더 명확한 결론으로 마무리하고 싶다.

## 실패 조건

- train/test 성능 차이를 무시하면 과적합된 전략을 비즈니스 인사이트로 착각할 수 있다.
- 마스킹된 Kaggle 데이터의 임계치를 실제 금융 환경에 그대로 적용하면 위험하다.
- MLflow run name과 display model name 매핑이 어긋나면 최신 모델 로드가 실패한다.
