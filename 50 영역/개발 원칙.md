# 개발 원칙

## 개인 기준

- [[50 영역/개발 원칙/개인 Dev Rules|개인 Dev Rules]]: commit, branch, issue, docs를 중심으로 사용자가 프로젝트 회고에서 정리한 협업 기준이다. 보편적 표준으로 단정하지 않는다.

## 경험을 원칙으로 바꾸는 흐름

1. [[프로젝트 의사결정 로그]]에서 상황과 선택 근거를 확인한다.
2. [[프로젝트 실패와 디버깅 로그]]에서 관찰, 가설과 확인된 사실을 분리한다.
3. [[프로젝트 적용 로그]]에서 결과와 다음에 먼저 확인할 기준을 남긴다.

## 사실 근거와 함께 점검할 원칙

- [[HTTP 요청은 타임아웃과 실패 처리를 기본값으로 가져야 한다]]: 외부 경계는 성공 경로만으로 완료하지 않는다.
- [[학습 데이터와 평가 데이터는 모델 선택 전에 분리해야 한다]]: 결과를 보기 전에 평가 경계를 고정한다.
- [[RAG 평가는 검색과 생성을 분리해서 측정해야 한다]]: 복합 시스템은 실패 위치를 나눠 기록한다.
- [[CSRF 방어는 브라우저 세션 요청의 출처를 검증한다]]: 편의를 위해 요청의 보안 경계를 지우지 않는다.

위 영구 노트는 사실 근거를 제공하고, 어떤 원칙을 우선하는지는 개인 판단으로 남긴다.
