# Query Expansion

태그: #rag #retrieval #llm_wiki

## 한 줄 정의

사용자 질문을 관련 표현이나 하위 질문으로 확장해 검색 범위를 넓히는 기법이다.

## 왜 중요한가

사용자 질문과 문서 표현이 다르면 관련 문서를 놓칠 수 있다. 질의 확장은 표현 불일치를 줄인다.

## 핵심 개념

- 동의어와 관련어를 추가한다.
- 여러 관점의 하위 질의를 만든다.
- 확장으로 잡음이 늘 수 있어 재정렬과 함께 쓴다.

## 예제

```text
"교차검증" -> "cross validation", "KFold", "model evaluation"
```

## 실무 활용

강의 용어가 한글/영문으로 섞인 자료 검색, FAQ 검색, RAG recall 개선에 활용한다.

## 내 말로 다시 설명

Query Expansion은/는 강의에서 나온 개념을 정의, 사용 조건, 주의점, 연결 개념으로 다시 설명하기 위한 LLM wiki 원자 노트다. 단순 암기보다 실제 문제에서 언제 꺼내 쓸지 판단하는 데 초점을 둔다.

## 언제 쓰는가

- 강의 실습 코드에서 같은 개념을 다시 만날 때
- 프로젝트에서 관련 오류나 설계 결정을 설명해야 할 때
- [[Retriever]], [[Reranking]], [[RAG]]와 함께 문제 원인을 좁힐 때

## 언제 쓰면 안 되는가

- 구체적인 API 버전, 파라미터, 보안 정책이 필요한 경우에는 공식 문서를 먼저 확인한다.
- 예제 하나만 보고 모든 상황에 일반화해야 할 때는 보류한다.
- 이미 더 좁고 구체적인 노트가 있는 경우에는 그 노트로 이동한다.

## 자주 헷갈리는 점

- 이름이 비슷한 인접 개념과 책임 범위가 다를 수 있다.
- 강의 예제의 상황과 실제 프로젝트의 데이터, 환경, 버전 차이를 분리해야 한다.
- "동작한다"와 "운영에서 유지보수 가능하다"는 다른 기준이다.

- 실제 프로젝트에 적용하면 먼저 검증해야 할 실패 조건은 무엇인가?
