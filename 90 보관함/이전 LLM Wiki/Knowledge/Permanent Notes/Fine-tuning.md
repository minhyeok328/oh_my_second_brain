# Fine-tuning

태그: #llm #finetuning #llm_wiki

## 한 줄 정의

사전학습 모델을 특정 데이터와 과제에 맞게 추가 학습하는 과정이다.

## 왜 중요한가

프롬프트만으로 일관된 스타일이나 도메인 출력을 얻기 어렵다면 fine-tuning을 고려할 수 있다.

## 핵심 개념

- 데이터는 입력-출력 예시로 정리한다.
- 검증셋으로 과적합과 품질을 확인한다.
- RAG로 해결할 지식 주입과 fine-tuning으로 해결할 행동 학습을 구분한다.

## 예제

```jsonl
{"messages": [{"role": "user", "content": "..."}, {"role": "assistant", "content": "..."}]}
```

## 실무 활용

일관된 답변 형식, 도메인 말투, 특정 분류/변환 작업을 모델에 학습시킬 때 사용한다.

## 내 말로 다시 설명

Fine-tuning은/는 강의에서 나온 개념을 정의, 사용 조건, 주의점, 연결 개념으로 다시 설명하기 위한 LLM wiki 원자 노트다. 단순 암기보다 실제 문제에서 언제 꺼내 쓸지 판단하는 데 초점을 둔다.

## 언제 쓰는가

- 강의 실습 코드에서 같은 개념을 다시 만날 때
- 프로젝트에서 관련 오류나 설계 결정을 설명해야 할 때
- [[LLM]], [[SLLM]], [[RAG]]와 함께 문제 원인을 좁힐 때

## 언제 쓰면 안 되는가

- 구체적인 API 버전, 파라미터, 보안 정책이 필요한 경우에는 공식 문서를 먼저 확인한다.
- 예제 하나만 보고 모든 상황에 일반화해야 할 때는 보류한다.
- 이미 더 좁고 구체적인 노트가 있는 경우에는 그 노트로 이동한다.

## 자주 헷갈리는 점

- 이름이 비슷한 인접 개념과 책임 범위가 다를 수 있다.
- 강의 예제의 상황과 실제 프로젝트의 데이터, 환경, 버전 차이를 분리해야 한다.
- "동작한다"와 "운영에서 유지보수 가능하다"는 다른 기준이다.

- 실제 프로젝트에 적용하면 먼저 검증해야 할 실패 조건은 무엇인가?
